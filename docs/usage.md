# 여러 사업 실적 통합 대시보드 사용 방법

## 실행

프로젝트의 `index.html`을 Chrome 또는 Edge에서 엽니다. 서버, 설치, 인터넷 연결이 필요하지 않습니다. `index.html`과 `js`, `css` 폴더를 함께 보관하세요.

기본 자료는 코드에 포함된 2024·2025·2026 CSV의 18행입니다. 원본 CSV를 `fetch`로 자동 읽지 않습니다. 원본 CSV 파일은 변경하지 않습니다.

## 확인 순서

1. 처음 열면 참여 1,410명, 수료 1,171명, 수료율 약 83%, 사업 6개, 선택 연도 3개가 표시됩니다.
2. 분야별 참여 비중 파이, 사업별 참여·수료 막대, 연도별 수료율 꺾은선과 18행 상세 표를 확인합니다.
3. 연도 선택을 바꿔 요약·차트·표가 함께 바뀌는지 확인합니다.
4. CSV 다운로드를 누르면 현재 선택 연도의 유효 행이 원본과 같은 한글 7열 순서로 저장됩니다.
5. 새 CSV를 선택할 때 2024.csv·2025.csv·2026.csv를 함께 선택하면 정상 자료를 직접 읽을 수 있습니다. 새 선택은 기존 자료를 대체합니다.
6. 오류 확인은 정상 파일과 섞지 않고 `data/programs/errors.csv` 하나만 선택합니다. 유효 2행, 제외 3행, 참여 20명, 수료 15명, 수료율 75%가 기대값입니다. 0명 행은 계산 불가이고 제외 이유에는 중복·숫자 누락·수료자 초과가 나옵니다.
7. 내려받은 CSV를 다시 선택해 같은 집계가 표시되는지 확인합니다. 기본 자료 복원으로 처음 상태로 돌아갑니다.

## 계산 기준

수료율은 합산 수료자 ÷ 합산 참여자 × 100입니다. 기본 주의 기준은 개별 행의 수료율 70% 미만입니다. 사업 수는 선택된 유효 행의 고유 사업 ID 수이고, 주의 항목 수는 사업·연도 행 단위입니다. 0명 행은 주의 항목에 포함하지 않습니다.

색상은 아름다운가게 CI의 초록 계열을 참고한 유사 색상이며 공식 CI 색상값을 인증한 결과물은 아닙니다. 자료는 교육용 가상 자료입니다.

## 에이전트 실행 기록의 한계

기준·계산·화면 담당은 별도 에이전트 생성 요청에서 `model="gpt-6-luna"`, `reasoning_effort="high"`, `fork_turns="none"`을 명시했습니다. 독립 검증에는 `model="gpt-6.1-sol"`, `reasoning_effort="medium"`, `fork_turns="none"`을 사용합니다. 제공된 역할 TOML의 업무와 제약을 각 담당에게 전달합니다.

현재 도구의 생성 반환은 작업 이름만 제공하며, 실제 해석된 모델과 추론 수준 메타데이터는 제공하지 않습니다. 요청 설정과 실제 실행 모델 확인을 구분합니다. 조율 대화의 실제 모델도 여기서는 확정할 수 없습니다.

Windows 브라우저 확인 도구는 현재 URL을 확신할 수 없어 이번 턴의 Computer Use를 중단했습니다. 실제 브라우저 표시 확인은 완료했다고 주장하지 않습니다. 사용자가 위 실행 순서로 화면을 확인할 수 있습니다.
